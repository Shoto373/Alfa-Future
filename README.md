# Альфа.Пульс — новостная аналитика для руководителей крупного бизнеса

Прототип для кейса «Новостная аналитика для принятия бизнес-решений» (Альфа-Банк × Changellenge, 2026).

Сервис в интерфейсе Альфа-Бизнеса превращает поток новостей и аналитику Альфа-Банка в персональные бизнес-инсайты. Для конкретной компании и роли пользователя он отвечает на шесть вопросов кейса:

1. Что произошло?
2. Почему это важно именно этой компании?
3. Какие возможны риски и возможности?
4. Что можно сделать?
5. Как это оценивает банк?
6. На чём основан вывод?

Каждое утверждение помечено происхождением: **факт из новости**, **данные компании**, **позиция Альфа-Банка** (тезис с документом и страницей) или **вывод AI**.

Демо: https://pointers-team.online · API и Swagger: https://pointers-team.online/docs

## Что умеет

| Требование кейса | Реализация |
|---|---|
| Контекст компании | ETL из CSV кейса. Учитывает отрасль по ОКВЭД, масштаб, место и долю в отрасли внутри выборки, продукты банка, ВЭД и страны, надёжность группы, контрагентов по платежам (отрасли, концентрацию), связи через физлиц и проблемы качества данных |
| Отбор и ранжирование | Скоринг «новость × компания × роль» с объяснимыми причинами (экспозиции компании, упоминание отрасли, страны ВЭД, фокус роли, свежесть) |
| Интерпретация | Агент, связка «экспозиция × направление события × позиция банка». Риски и возможности собираются по темам из нескольких признаков, к ним добавляется горизонт по прогнозу банка. Действия и вопросы зависят от роли и наличия продуктов |
| Агентная логика | План → инструменты (только чтение, аудит, бюджет вызовов) → общий контекст → черновик (LLM или правила) → 7 проверок качества → коррекция (расширить поиск, убрать неподтверждённое, дополнить) → трасса |
| Аналитика банка | База знаний: 43 тезиса из 9 материалов ЦМА и Альфа-КИБ со страницами, датами и пометкой устаревших. Противоречия между прогнозами разных дат выявляются явно |
| Парсер | RSS (Банк России, Интерфакс, РБК, ТАСС, Коммерсантъ), загрузка статьи по ссылке с защитой от SSRF, классификация (темы, направление по теме, отрасли, страны, участники, даты, числа), ключевые предложения, дедупликация |
| Интерфейс Альфа-Бизнеса | Вход под демо-пользователем (у одной компании несколько людей с разными ролями). На главной постоянная точка входа: пункт меню, баннер и плавающая кнопка. Персональная лента, разбор новости, ход анализа, уточняющие вопросы, переход к первоисточнику (PDF на нужной странице), оценки |
| Мониторинг | Метрики контента, персонализации и AI, обратная связь по разделам, журнал обращений к инструментам |

## Архитектура

```
Браузер ──► frontend (Next.js 16, :3000) ──► backend (FastAPI, :8000)
                                               ├─ companies: ETL CSV → профили и экспозиции
                                               ├─ news: RSS/URL → классификатор → хранилище с дедупликацией
                                               ├─ knowledge: тезисы аналитики банка, BM25-поиск
                                               ├─ ranking: новость × компания × роль
                                               ├─ agent: план → инструменты → черновик → самопроверка → трасса
                                               │        └─ LLM (OpenAI-совместимый API, только модели кейса) — по желанию
                                               └─ storage: карточки, отзывы, метрики, аудит (RUNTIME_DIR)
```

### Агентный цикл

1. **План.** LLM или правила выбирают инструменты из закрытого реестра. Поиск по аналитике банка обязателен.
2. **Инструменты.** Только чтение, с проверкой аргументов и бюджетом в 16 вызовов. Каждый вызов пишется в журнал:
   - профиль компании, экспозиции и новость;
   - поиск по аналитике банка;
   - связанные новости;
   - контрагенты;
   - продукты банка;
   - сверка прогнозов банка.
3. **Контекст.** Результаты шагов собираются в общий контекст, на нём строится черновик.
4. **Черновик.** LLM получает контекст в JSON и обязана ссылаться только на переданные источники. Без LLM черновик строится правилами: эффект = чувствительность компании × направление события.
5. **Самопроверка.** Семь проверок: полнота, источники, позиция банка только из материалов банка, найдена аналитика, цифры подтверждены, нет противоречий с данными клиента, вывод персонализирован.
6. **Коррекция.** До двух раундов: расширить поиск, убрать неподтверждённое, дополнить разделы.
7. **Трасса.** Каждый шаг виден в блоке «Как получен вывод».

### Безопасность

| Риск | Мера |
|---|---|
| Неразрешённые модели, перерасход | allowlist моделей кейса, дневной лимит токенов |
| Prompt injection из новостей | тексты передаются как данные в JSON, ответы проходят проверку источников |
| Опасные действия агента | инструменты только на чтение, закрытый реестр, бюджет вызовов, журнал `audit.jsonl` |
| SSRF при загрузке ссылок | только http/https, запрет внутренних адресов на каждом редиректе, лимиты размера и времени |
| Утечка данных | данные кейса не попадают в Git и образы, в логах только метаданные |
| Права (продакшен) | пользователь видит только свои компании через интернет-банк, роль берётся из IAM; в прототипе — демо-вход |

### Масштабирование и мониторинг

- **Новые отрасли, темы и источники.** Достаточно добавить строки в таблицы `companies/sectors.py`, `news/taxonomy.py` и `RSS_SOURCES`. Новые материалы банка добавляются в `knowledge/bank_analytics.json`.
- **Продакшен.** PostgreSQL вместо JSON, отдельный воркер RSS и векторный индекс. Контракт API при этом не меняется.
- **Метрики** (`/api/v1/metrics`, страница «Качество и аудит»):
  - доля разборов, прошедших самопроверку с первой попытки;
  - доля выводов со ссылкой на источник;
  - открытия и оценки «полезно» по разделам;
  - режим LLM, токены, длительность.
- **Процесс.** Регулярная экспертная разметка выборки разборов, разбор слабых разделов, правка тезисов, чувствительности и промптов.

## Требования

- Docker с Compose v2. Больше ничего не нужно.
- Для разработки без Docker: Python 3.11+, Node.js 20.9+.

## Запуск

```bash
cp .env.example .env               # по желанию: ключ LLM, пути к данным кейса
docker compose -f compose.yaml up --build -d
docker compose -f compose.yaml ps  # backend и frontend — healthy
```

Откройте http://localhost:3000 и выберите демо-пользователя.

По умолчанию используется **синтетический набор** `data/synthetic` той же схемы, что и в кейсе (помечен файлом `SYNTHETIC`). Реальные данные кейса в репозиторий не входят, их подключают монтированием:

```bash
CASE_DATA_DIR=/путь/к/csv BANK_PDF_HOST_DIR=/путь/к/pdf docker compose -f compose.yaml up --build -d
```

`CASE_DATA_DIR` — каталог с `df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv` и `df_Fid_Uid_link_hack.csv`. `BANK_PDF_HOST_DIR` — PDF аналитики банка: из него раздаются первоисточники. Профили строятся при старте (около 20 с на полном наборе) и кэшируются. При изменении данных кэш пересобирается сам.

> В корне есть ещё `docker-compose.yml` для прод-деплоя (nginx + HTTPS). Локально всегда указывайте `-f compose.yaml`.

### Подключение LLM

Без ключа агент работает в **режиме правил**: весь сценарий проходится, карточки помечены «Агент на правилах». Чтобы включить LLM, заполните `.env` и перезапустите backend:

```
LLM_BASE_URL=https://changellenge.up.railway.app/v1   # запасной: https://api.alfahack-gateway26.ru/v1
LLM_API_KEY=<ключ команды>
LLM_MODEL_REASONING=z-ai/glm-5.3-flash                # интерпретация
LLM_MODEL_FAST=deepseek/deepseek-v4.1-flash           # план и ответы на вопросы
LLM_DAILY_COST_LIMIT=450                              # ₽ в день, бюджет ключа — 500 ₽
```

Разрешены только модели из Приложения 3 кейса: Gemma 4 26B A4B, GLM-5.3-Flash, Qwen3.6 35B A3B, DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B-Instruct и Kimi-K2.6. Другие имена backend отклоняет. При ошибке модели агент переключается на правила, и это видно в трассе.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATA_DIR` | `data/synthetic` | каталог CSV кейса (в Docker — `/data/case`) |
| `FALLBACK_DATA_DIR` | `data/synthetic` | набор на случай, если в `DATA_DIR` нет CSV |
| `RUNTIME_DIR` | `data/runtime` | профили, новости, карточки, отзывы, аудит (в Docker — том `runtime`) |
| `BANK_PDF_DIR` | — | PDF аналитики банка для перехода к первоисточнику |
| `LLM_*` | — | см. выше |
| `RSS_SOURCES` | 5 лент | `имя|url` через запятую; пустая строка — без RSS |
| `RSS_REFRESH_MINUTES` | `0` | автообновление ленты (0 — только кнопкой) |
| `ANALYSIS_TIMEOUT_SECONDS` | `150` | тайм-аут подготовки разбора |
| `FRONTEND_ORIGIN` | `http://localhost:3000` | единственный origin для CORS |
| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:8000` | адрес API для браузера, задаётся при сборке frontend |

## Сценарий проверки

1. **Вход.** На http://localhost:3000 выберите, например, «Анна Морозова · Финансовый директор» первой компании.
2. **Главная.** Блок «Альфа.Пульс» показывает три самые важные для компании новости и причины их отбора. Сервис также доступен из меню и по плавающей кнопке.
3. **Лента** («Открыть ленту»). Новости отсортированы по релевантности, у каждой есть объяснение («Есть депозиты: …», «ВЭД с контрагентами: Китай»). Справа контекст компании: место в отрасли, продукты, поставщики и покупатели по отраслям, качество данных.
4. **Персонализация.** Смените роль в шапке на «Руководитель казначейства» или выберите другую организацию: лента перестроится.
5. **Разбор.** Нажмите «Разобрать для компании» у новости о ключевой ставке. Откроются шесть разделов кейса, позиция Альфа-Банка выделена отдельно, у каждого утверждения есть происхождение и ссылки [n] на источники.
6. **Трассировка.** «Как получен вывод» показывает план, вызовы инструментов, черновик, самопроверку и коррекции.
7. **Первоисточник.** В разделе 6 ссылка «Первоисточник» открывает PDF банка на нужной странице (при смонтированных PDF).
8. **Уточняющий вопрос.** «Покажи в разрезе контрагентов», «Какое место компании в отрасли?» или свой вопрос.
9. **Новая новость.** В ленте «Проверить свою новость»: вставьте любой текст или ссылку, сервис классифицирует и разберёт её.
10. **Качество.** «Качество и аудит» показывает метрики, результаты проверок и журнал обращений агента к инструментам.

## Ограничения прототипа

- Демо-лента пересказывает события из материалов кейса. Живые новости приходят из RSS (кнопка «Обновить из RSS» или `RSS_REFRESH_MINUTES`).
- Доля и место компании считаются внутри набора данных кейса, а не по всему рынку. Это явно указано в интерфейсе.
- Без LLM интерпретация строится детерминированными правилами. С LLM действуют те же ограничения на источники и проверки.
- Аутентификация упрощена до выбора демо-пользователя. Разграничение прав для продакшена описано в архитектуре.
- Материал не является инвестиционной рекомендацией.
