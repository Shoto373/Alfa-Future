# Версии API и каталог ошибок

Публичный контракт — `contracts/openapi.json`, версия **1.2.0** (`API_VERSION` в `backend/app/schemas.py`, заголовок `X-API-Version` в каждом ответе). Формат разбора — отдельная версия **1.0.0** (`SCHEMA_VERSION`, поле `schema_version` в разборе): он меняется, только если меняются поля разбора.

## История версий

| Версия | Что изменилось |
|---|---|
| 1.2.0 | Аддитивно (спринт 4): доменная конфигурация `/admin/config` — темы, отрасли и действия как данные (просмотр, проверка, превью ленты, публикация, откат); потоковый разбор `GET /insights/stream` (SSE; синхронный `POST /insights` остается); контрагенты компании `GET /companies/{id}/counterparties`; сценарии «что если» `POST /scenarios` |
| 1.1.0 | Аддитивно (спринт 3): `GET /news/{id}?company_id=` — организации в новости и их отношение к компании; экран аналитика `/admin/kb/*` (загрузка PDF, черновики тезисов, публикация); разметка ленты `/admin/labeling/*`; вход через Альфа-ID `/auth/methods`, `/auth/oidc/*`. Формат разбора не менялся (1.0.0) |
| 1.0.0 | Первая закрепленная версия (SPR3-00) |

## Политика версий

| Изменение | Версия | Пример |
|---|---|---|
| Новое необязательное поле, новый адрес, новое значение в перечислении для нового сценария | минорная: 1.0.0 → 1.1.0 | поле `effect` в разборе |
| Исправление описания без изменения данных | патч: 1.0.0 → 1.0.1 | уточнение текста схемы |
| Удаление поля, переименование, смена типа или смысла поля, новое обязательное поле запроса | только новый префикс `/api/v2` | — |

Старые клиенты продолжают работать на `/api/v1` до отдельного решения о выводе версии из эксплуатации. Поле, которое сервер всегда отдает, помечено в контракте обязательным, даже если в модели у него есть значение по умолчанию.

## Как меняется контракт

1. Изменить схемы в `backend/app/schemas.py` (или `app/auth/schemas.py`) аддитивно.
2. `cd backend && python tools/gen_contracts.py` — обновить `contracts/openapi.json`.
3. `cd frontend && npm run gen:api` — обновить `frontend/lib/api-types.ts`; код интерфейса берет имена из `lib/types.ts`.
4. Закрепленные примеры `contracts/examples/*.json` не меняются: тест проверяет, что примеры 1.0.0 валидны для текущих схем — это и есть обратная совместимость.

CI падает, если `contracts/openapi.json` или `frontend/lib/api-types.ts` расходятся со схемами (`git diff --exit-code`).

## Формат ошибки

```json
{"error": {"code": "FORBIDDEN", "message": "Недостаточно прав", "request_id": "req_…", "retryable": false}}
```

`retryable: true` — повтор того же запроса может помочь (сервис временно недоступен или не успел); интерфейс показывает кнопку «Повторить» только для таких ошибок.
