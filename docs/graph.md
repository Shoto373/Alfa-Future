# Граф контрагентов (SPR4-01)

## Как строится

`backend/app/companies/graph.py` читает те же CSV кейса, что и профили:

- `df_Uid_payment_hack.csv` (PAYER, BENEFICIARY, PAY_AMT, PAY_CNT) дает ребро «плательщик → получатель». Для плательщика получатель — поставщик, вес ребра равен доле в его исходящих платежах. Для получателя плательщик — покупатель, вес равен доле во входящих платежах. Платежи самой себе не учитываются.
- `df_Fid_Uid_link_hack.csv` дает связи через общих физлиц. Это отдельный тип ребра с весом 0,1 и подписью «возможная связь». Вывода о юридической аффилированности нет.

Второй уровень — контрагенты контрагентов первого уровня с долей от 5%. Вес цепочки равен доля₁ × доля₂. Цепочка учитывается при весе от 2%. Объяснение строится так: «вы → поставщик А (32% закупок) → его поставщик Б (51%)».

Граф строится один раз на подпись данных кейса в каждом процессе. Воркер сохраняет ребра в `company_edges` (задача `counterparty_monitor`, каждые 5 минут, только при смене данных).

## Где используется

- **Мониторинг** (`app/monitoring.py`): новость, где организация из `news_entities` (SPR3-02) — контрагент компании до второго уровня, создает алерт с цепочкой и силой события. Он сохраняется один раз на пару «компания × новость × контрагент».
- **Лента**: признак `counterparty` (вес в `ranking_weights.json`) и причина «Касается контрагента второго уровня: вы → … → …». Прямые контрагенты по-прежнему учитываются признаком `mention`.
- **Разбор**: инструмент агента `lookup_counterparty_chain(company_id, news_id)`. Он вызывается, только если в новости названы организации. Вывод «Новость касается вашего поставщика второго уровня: …» имеет origin `client_data` и источник `client:graph`.
- **Экран «Контрагенты»** (`/pulse/counterparties`): топ-20 по платежам, второй уровень, возможные связи и события. Компании вне профилей показаны только идентификатором из данных кейса.
